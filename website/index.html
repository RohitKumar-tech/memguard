Memory you can audit, and undo, for AI agents

AI agents that use MCP tools and n8n workflows remember things between sessions. If an attacker gets one false entry into that memory, it can steer every later session. MemGuard records where each memory came from, holds risky actions for a human, and can roll a poisoned entry back together with everything derived from it.

The problem

Most prompt-injection defenses inspect what goes into the model. Memory poisoning happens earlier: a malicious sentence is saved once, looks like a normal preference or fact, and is retrieved and trusted in every later session.

Recent benchmark work reports that existing prompt-injection defenses do not cover this case, and that protection has to include storage-time provenance, versioning and retention policy, not only checks at retrieval or execution time.

An example

An agent summarizes a vendor email. Hidden text in the email says to always BCC an outside address on invoices. The agent saves that as a user preference. Two days later it sends an invoice, and the attacker gets a copy.

Nothing was wrong with the second request. The damage was done when the entry was stored.

What MemGuard does

Four mechanisms, enforced in code at the point where the agent touches memory and tools, not in the prompt.

  1. Provenance on every write

    Each memory is labelled with its source and a trust level: the user, a verified internal system, or untrusted tool output. A summary built from several memories takes the lowest trust of its inputs. Unknown sources are treated as untrusted.

  2. Write-time detection

    A fine-tuned DeBERTa-v3-small model and lexical rules flag instruction-like text from untrusted sources and quarantine it before the agent can read it.

  3. Risk-adaptive approval

    An action is held for a human when a high-impact parameter, such as an external CC address or a payee account, comes only from untrusted-origin memory. Values the user supplied, or that stay inside the organization, pass without friction.

  4. Versioning and rollback

    Memory is an append-only log chained with SHA-256. When a reviewer rejects an entry, MemGuard finds everything derived from it, rolls it back, and re-derives those memories from their clean sources.

What the evidence says

Provenance does the work

Provenance labels plus the risk engine cut attack success from 83.1% to 3.3% while completing 99.9% of benign tasks.

The detector alone is weak

It scored an F1 of 0.99 on its own test set but 0.30 on a different public dataset, and it flags about 10% of benign writes.

Trusted channels are the gap

If poison is written through a channel labelled trusted, MemGuard offers no protection. Scanning trusted writes halves the attack but blocks many legitimate tasks.
