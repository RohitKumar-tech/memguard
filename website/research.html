Background and reproducibility

What this project builds on, how to reproduce the numbers, and what it does not claim.

Abstract

LLM agents built on MCP tools and n8n workflows keep notes, preferences and retrieved facts across sessions, which makes long-term memory an attack surface: one poisoned entry can steer every later session. Existing prompt-injection defenses act on inputs and do not cover entries that are already stored. MemGuard is a gateway that records the provenance of every memory write, quarantines instruction-like text from untrusted sources, holds high-impact actions that depend on untrusted memory, and keeps memory in a hash-chained, versioned log so a poisoned entry and everything derived from it can be rolled back and re-derived. On a synthetic benchmark of 1,800 episodes it reduces attack success from 83.1% to 1.0%, with provenance and the risk engine responsible for most of the effect. It offers no protection when poison arrives through a channel it trusts.

Related work

  • AgentPoison (Chen et al., NeurIPS 2024) and MINJA (Dong et al., 2025) show poisoned entries can be planted in an agent's memory or knowledge base, the latter through ordinary queries alone.
  • CaMeL (Debenedetti et al., 2025) separates privileged and quarantined models and tracks data flow with capabilities. It targets in-session tool use rather than durable memory.
  • Greshake et al. (AISec 2023) introduced indirect prompt injection against LLM-integrated applications.
  • MPBench (ICML 2026) gives a taxonomy and benchmark for memory poisoning and reports that existing prompt-injection defenses miss it.
  • APPA (arXiv:2607.24625) proposes recoverable information-flow control, and two 2026 surveys (arXiv:2604.16548, arXiv:2604.23338) call for storage-time provenance, versioning and retention policy.

MemGuard's contribution is to combine provenance, a risk engine and dependency-aware rollback at the memory-write boundary, and to measure what each contributes, including where the combination fails.

Reproduce the results

Everything runs on a single laptop GPU. Training the detector takes about two minutes; the full evaluation takes a few minutes per configuration.

pip install fastapi uvicorn numpy pandas pyarrow scikit-learn torch \
            transformers sentence-transformers matplotlib pytest mcp

python scripts/get_data.py             # public datasets from Hugging Face
python train/train_detector.py         # fine-tune DeBERTa-v3-small
python -m pytest -q tests              # 8 unit tests
python bench/run_eval.py --n 600 --seeds 3 --tag main
python bench/run_eval.py --n 600 --seeds 3 --tag trusted_channel --poison-source user
python bench/make_plots.py

Data

  • deepset/prompt-injections (Apache-2.0), 662 labelled prompts.
  • xTRam1/safe-guard-prompt-injection, 10,296 labelled prompts, largely synthetic.
  • MemBench-Lite, generated by the project from fixed seeds. Poison text reuses real injection strings from the public data.

Datasets are downloaded by the script and not redistributed. Check each dataset card for its licence before reuse.

What this does not claim

  • It does not show that any particular language model is safe or unsafe. The agent is scripted.
  • It does not compare against published benchmarks. The benchmark is synthetic and authored by the project.
  • It does not solve poisoning through trusted channels. The stress test shows 99% attack success there.
  • It does not evaluate real reviewers. Approval burden is reported in counts, not in human time.
  • The n8n workflow has not been executed on a running n8n instance.
  • No commercial product and none of the published memory-poisoning defenses was run head-to-head, so no claim is made against them.
